# ModBox

自用的多游戏模组管理器。Electron + Vue 3，Windows 桌面端。

## 它解决什么问题

手动给游戏装模组很烦：每个游戏的目录结构不一样，有的要放根目录，有的要进 `~Mods`，有的要按加载器拆插件，还经常遇到只读文件删不掉、路径记不住、装完不知道有没有生效。ModBox 把“识别包结构 → 投放到正确位置 → 卸载时还原/清理”这套流程固定下来，按游戏配置规则，装的时候不用再翻 Nexus 说明。

## 核心能力

**按游戏规则安装**。每个游戏在 `builtinGames.js` 里配一份 `installRules`，包含 `placements`（匹配哪些文件/目录、投放到哪）和 `cleanup`（清理哪些目录、移除哪些代理文件）。安装时由 `buildPlan` 生成投放计划，冲突直接报错，不会糊里糊涂覆盖。

**安装/卸载有记录**。装过的文件写进 manifest，卸载时按记录删文件、还原被覆盖的官方文件；清理时先走 manifest 卸载，再按 `cleanup.actions` 清目录和残留文件。

**Steam 路径自动检测**。按 `steamAppId` 查 Steam 库和注册表，找到游戏根目录后自动拼 `exeRelative`，查不到再手动选。

**文件选择器记忆位置**。选过一次目录/文件后，下次 dialog 从上次位置打开。

## 已适配

黑神话：悟空、赛博朋克 2077、天国：拯救2、荒野大镖客：救赎2、生化危机9：安魂曲、只狼：影逝二度、剑星。

各游戏的加载器前置（UE4SS、KCSE、LML、CNS 等）部分靠规则处理，部分需手动装一次，规则里用 `^` 前缀区分“只匹配顶层”和“匹配任意层级”。

## 已知问题

- 编辑模组信息功能未完成
- 模组封面显示偶有问题
- 两个 mod 抢同一文件时直接报错中止，没有“覆盖/跳过”策略
- 层数不固定的 mod 包（外层说明文件夹 + 内层 mod 文件夹）靠 `lift` 猜，`lift` 写死会在一部分包上错位
- 代码结构偏乱，部分模块待拆分

## 技术栈

Electron、Vue 3、Vite、Pinia、vuedraggable。
